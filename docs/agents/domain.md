# Domain docs

This repo uses a single-context layout: `GLOSSARY.md` at the root and ADRs in `docs/adr/`.

Before exploring a domain area, read `GLOSSARY.md` and relevant ADRs in `docs/adr/` when they exist. Proceed if they have not been created yet; the domain-modeling skill creates them as terms and decisions are resolved.

Use the glossary's terms in issues, proposals, hypotheses, and tests. If a needed concept is absent, reconsider the term or note the gap for domain modeling.

Surface any conflict with an existing ADR explicitly.
